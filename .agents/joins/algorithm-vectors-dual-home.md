# Algorithm golden vectors: dual home intentional?

Date: 2026-08-01
Repo: `/home/hunter/Projects/surmount/libbitcoinpqc-bindings`
Question: Is `tests/vectors/fixtures/` + generated language/C copies accidental dual SoT, or intentional single-authoring + derivatives?

## Executive answer

**Intentional single authoring home + committed generated derivatives, with CI/local enforcement.**
Not an accidental dual SoT for algorithm goldens.

Evidence is **strong** (script docstring, headers, README, plan, Makefile/just/CI/flake all agree). Residual risks are mostly **operator path confusion** (standalone vs submodule C headers) and **flake not snapshotting C headers**, not "two equal authoring homes."

## 4. Why copy into C headers / multiple languages?

Documented reasons (plan + design), not archaeology-only:

1. **Language-native consumption:** C ctest needs `#include` static byte arrays; Rust wants `const &[u8]`; Node/WASM want modules; Python wants importable constants. One JSON cannot satisfy all without a runtime loader each language does not share.
2. **C headers stay in libbitcoinpqc** so upstream CMake/tests keep working without rewiring include paths into the bindings monorepo layout.
3. **Committed derivatives** let CI and offline tests run without regenerating first (regen is a *consistency* gate, not a build step every test needs).
4. BIPs handoff: algorithm goldens live in bindings; construction vectors are separate (`p2mr/`).

Not evidence of two independent authoring workflows for the same crypto bytes.

## 5. Failure modes (does CI catch?)

| Mistake | What happens | Caught? |
|---------|----------------|---------|
| Edit **only** a generated file (e.g. `rust/*.rs` or a `.h`) | CI/just re-runs sync from fixtures → overwrites/restores canonical form → `git diff` non-empty if hand-edit differed | **Yes** (GHA + `just vectors-in-sync`) |
| Edit **only** `fixtures/*.json`, forget sync | Sync rewrites all derivatives → diff vs committed generated files | **Yes** |
| Edit fixture + regenerate + commit all langs + C in submodule | Clean | **OK** (intended path) |
| Local `make sync-vectors` with **standalone** `~/Projects/surmount/libbitcoinpqc` present | C headers land **outside** the submodule; submodule headers stale | **Local yes if using `just vectors-in-sync`** (forces submodule). **GHA yes** (no standalone path; uses submodule). Developer who only runs `make sync-vectors` can think they're synced while submodule is dirty/stale until they notice. |
| Drift in **standalone** upstream libbitcoinpqc checkout vs submodule | Bindings CI only gates **submodule** tree | **Not fully** cross-repo; operator must push/sync standalone separately |
| Flake `vectors-in-sync` only | Snapshots fixtures+lang dirs only | **C header drift not covered** by flake check alone |
| Edit destination **and** fixtures inconsistently, then run sync | Sync forces destinations = fixtures | Fixtures win; destination-only intent lost (good for SoT) |

GHA uses **full-tree** diff after sync (stricter / noisier if unrelated dirt). Local just scopes to algorithm vector paths so WIP elsewhere does not fail the gate.

## 6. Conclusion taxonomy

| Label | Fits? |
|-------|--------|
| **Intentional single authoring + generated derivatives (enforced)** | **Yes** for algorithm goldens |
| Messy dual homes that can drift unchecked | **No** as the designed model; drift is actively gated in GHA/`just`/`ci` |
| Hybrid | Soft hybrid only for: (a) committed derivatives look like "second homes" in the tree, (b) C may also live in a standalone upstream checkout outside CI, (c) Python banners weaker, (d) flake omits C |

**Separate issue (do not conflate):** P2MR construction JSON under `tests/vectors/p2mr/fixtures/` vs workshop copies is a different dual-copy story (hand-maintained, not `sync-golden-vectors`). Inventory of that is in `fixture-sot-inventory.md`.

## Risks that remain

1. **Cognitive dual home:** many generated paths look editable; only some have strong "do not edit" banners (Python weak).
2. **`make sync-vectors` vs `just vectors-in-sync`:** standalone preference can update the wrong C tree locally.
3. **Submodule + upstream split:** C headers must land in submodule (and ideally standalone) when crypto vectors change; CI only enforces submodule in this repo.
4. **Flake gap:** hermetic `vectors-in-sync` does not assert C header content.
5. **Committed bulk:** large hex in many languages means big diffs when vectors change (by design, not a SoT bug).

## Bottom line for the skeptic

The dual *form* is intentional: **JSON authors once; sync materializes language-native committed artifacts; gates re-run sync and fail on drift.**
It is **not** two equal sources of truth for algorithm golden bytes. Fixtures are the only authoring SoT; everything else is derivative under enforcement (with the caveats above).
